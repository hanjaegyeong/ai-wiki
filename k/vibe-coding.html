바이브 코딩

Vibe Coding

자연어로 원하는 걸 설명하면 AI가 코드를 통째로 만들어주는 개발 방식. "코드를 짜는" 게 아니라 "분위기를 전달하면 결과물이 나오는" 패러다임이다.

코드를 짜는 게 아니라 결과를 부르는 것

예전에는 앱 하나를 만들려면 함수 이름 하나, 세미콜론 하나까지 사람이 직접 타이핑해야 했다. 바이브 코딩은 그 관계를 뒤집는다. "이런 느낌의 할 일 앱을 만들어줘"라고 자연어로 말하면 AI가 코드를 생성하고, 사람은 결과를 보고 "여기 색 바꿔", "이 버튼 안 눌려" 식으로 다시 말로 고쳐 나간다. 용어를 만든 Andrej Karpathy는 이걸 두고 "사실 코딩이라기보단, 그냥 보고, 말하고, 실행하고, 복붙하는 것"이라고 표현했다. 코드가 존재한다는 사실 자체를 잊어버리는 감각에 가깝다.

2025년 2월의 트윗 한 줄에서 시작된 이 말은 그해를 지배했다. 코딩을 배운 적 없는 사람들이 주말에 앱을 만들어 올리기 시작했고, Collins 사전은 '바이브 코딩'을 2025년 올해의 단어로 선정했다. 신조어가 1년 만에 사전에 오른 건, 이 방식이 소프트웨어를 만들 수 있는 사람의 범위 자체를 바꿔 놓았기 때문이다. 아이디어는 있는데 구현할 손이 없어서 멈춰 있던 것들이 일단 돌아가는 형태로 세상에 나오기 시작했다.

언제, 어떻게 쓰나

개발자가 실제로 쓰는 장면은 대개 빠른 프로토타입이다. Cursor나 Claude Code에 "React로 드래그앤드롭 되는 칸반 보드, 데이터는 로컬스토리지에 저장"이라고 던지면 폴더 구조부터 컴포넌트, 스타일까지 한 번에 나온다. 주말에 아이디어를 검증하는 장난감 프로젝트, 비개발자가 머릿속 그림을 눈앞의 화면으로 바로 확인하는 용도, 혹은 개발자가 반복적인 보일러플레이트를 건너뛰고 본론으로 뛰어드는 데 특히 강하다. Replit, Lovable, v0처럼 브라우저에서 설명만 하면 배포까지 해 주는 도구들은 개발 환경 설정조차 몰라도 되게 만들었다. 핵심은 결과물을 계속 실행해 보면서 대화로 방향을 잡아 간다는 점이다. 코드를 읽고 판단하는 대신, 동작을 보고 판단한다. 개발자가 아닌 직군에도 쓰임새가 넓다. 기획자가 문서로 스펙을 쓰는 대신 동작하는 목업을 만들어 회의에 들고 오고, 데이터 담당자가 일회성 분석 스크립트를 말로 뽑아내는 식이다.

실전에서는 "감"만으로 배포하지 않는다

문제는 생성된 코드를 이해하지 못한 채 그대로 올릴 때 생긴다. 조사에 따르면 AI가 만든 코드의 상당수가 SQL 인젝션이나 권한 검사 누락 같은 잘 알려진 보안 결함을 그대로 품고 있고, 특히 인증·결제·개인정보를 다루는 부분일수록 위험이 크다. 구조 문제도 있다. 대화의 흐름대로 즉흥적으로 자란 코드베이스는 몇 주만 지나면 전체 그림을 아는 사람이 아무도 없는 상태가 되기 쉽고, 그 시점부터는 AI에게 고쳐 달라고 해도 수정이 다른 곳을 부수는 악순환에 빠진다. 겉으로는 잘 돌아가 보여서 문제를 늦게 발견한다는 점이 이 방식의 가장 위험한 성질이다. 그래서 실무에서는 UI 실험이나 내부 도구처럼 위험이 낮은 곳엔 가볍게 쓰되, 민감한 로직은 반드시 사람이 코드 리뷰하고 자동 보안 스캔을 거친다. API 키를 프런트엔드 코드에 그대로 박아 두는 것처럼, 경험자라면 하지 않을 실수가 코드를 안 읽는 만큼 걸러지지 않는다는 점도 기억할 필요가 있다. 주니어 개발자가 기본기를 쌓을 기회를 잃는다는 교육 관점의 우려와, 진입 장벽을 낮춰 더 많은 사람을 개발의 세계로 데려온다는 반론이 공존하는 것도 이 지점이다.

바이브 코딩 다음의 이름

Karpathy 본인도 2026년 들어 전문가의 작업에는 다른 이름이 필요하다며 에이전틱 엔지니어링을 제안했다. 코드를 직접 쓰지 않는 건 같지만, 감으로 결과만 보는 게 아니라 에이전트들에게 일을 나눠 주고 산출물을 검증하는 감독자로 일한다는 점이 다르다. 계획을 먼저 승인하고, 변경 단위를 작게 유지하고, 테스트로 검증하는 규율이 들어간다. 같은 도구를 쓰면서도 태도가 다른 것이다. 정리하면 이렇다. 바이브 코딩은 시작을 폭발적으로 빠르게 해주는 도구지, 검증을 생략해도 된다는 허가증이 아니다. 프로토타입은 바이브로, 프로덕션은 엔지니어링으로 — 무엇을 감으로 만들고 무엇을 규율로 지킬지 가르는 판단력이 이 시대의 새 기본기이고, 2026년 현재 실무의 합의점은 대략 여기에 와 있다.
