모델

멀티모달

Multimodal AI

텍스트뿐 아니라 이미지, 음성, 영상 등 여러 형태의 데이터를 하나의 모델이 동시에 이해하고 처리하는 AI.

보고 듣고 읽는 하나의 모델

초기 LLM은 텍스트만 다루는 모델이었다. 이미지를 이해시키려면 별도의 비전 모델로 캡션을 뽑아 텍스트로 넘겨주는 우회로를 써야 했고, 그 과정에서 정보가 뭉텅이로 사라졌다. 멀티모달 모델은 이미지, 음성, 영상, PDF 같은 여러 형태의 입력을 모델 하나가 직접 받아들인다. 스크린샷을 던지며 "이 UI에서 뭐가 어색해?"라고 묻거나, 손으로 그린 와이어프레임 사진을 주고 "이대로 HTML 만들어줘"라고 하거나, 회의 녹음을 통째로 넣고 요약을 받는 일이 전부 API 호출 하나로 처리된다. 핵심은 여러 모달리티가 텍스트로 번역되어 만나는 게 아니라, 모델 내부의 같은 표현 공간에서 섞인다는 점이다. 차트의 꺾은선과 그걸 설명하는 문장이 같은 어텐션 안에서 서로를 참조한다.

따로 배운 눈을 이어 붙이던 시대

기술적으로 멀티모달의 1세대는 접붙이기였다. 이미지를 이해하는 비전 인코더(CLIP 계열)를 따로 학습해 두고, 그 출력을 어댑터라는 작은 변환층으로 LLM의 토큰 공간에 투영해서 "이미지도 단어들처럼 보이게" 만드는 구조다. 오픈소스 LLaVA가 이 레시피를 대중화했고, GPT-4V를 비롯한 초기 상용 비전 모델들도 비슷한 계열이었다. 이 방식은 기존 LLM을 재활용할 수 있어 경제적이지만, 눈과 뇌를 따로 만들어 붙인 만큼 이미지 속 글자를 정밀하게 읽거나 여러 이미지를 비교 추론하는 데 한계가 드러났다.

네이티브 멀티모달로의 전환

2024~2026년의 흐름은 접붙이기를 버리고 처음부터 함께 배우는 네이티브 멀티모달로의 전환이다. 이미지 패치, 오디오 조각, 텍스트 토큰을 하나의 토큰 스트림으로 섞어 사전학습 단계부터 한 트랜스포머에 흘려 넣는 조기 융합(early fusion) 구조로, Gemini가 이 설계를 앞세웠고 GPT-4o의 실시간 음성 대화, Meta의 오픈 웨이트 Llama 4도 같은 방향이다. 입력만이 아니라 출력도 멀티모달이 되어, 하나의 모델이 대화 중에 이미지를 그려서 답하는 것까지 자연스러워졌다. 문서 이해 성능이 크게 오른 것도 이 세대의 특징이라, 표와 그래프가 섞인 수십 페이지 PDF를 통째로 넣고 질문하는 것이 이제 실무에서 통하는 패턴이 됐다.

개발자가 실제로 쓰는 장면

Claude API라면 메시지의 content 배열에 텍스트 블록과 이미지 블록을 나란히 넣는 것으로 끝난다. 자주 쓰이는 패턴은 몇 가지로 수렴한다. 디자인 시안이나 스크린샷을 주고 프론트엔드 코드를 생성시키는 것, E2E 테스트 실패 시점의 화면을 캡처해 원인을 분석시키는 것, 아키텍처 다이어그램을 읽혀 문서를 만들게 하는 것, 스캔 문서·영수증에서 구조화된 데이터를 뽑는 OCR 대체다. Claude Code 같은 코딩 에이전트가 스크린샷을 읽고 UI 버그를 고치는 것도 같은 능력이고, 이를 한 단계 밀어붙이면 모델이 화면을 직접 보며 마우스와 키보드를 조작하는 컴퓨터 사용(computer use) 에이전트가 된다. 검색 쪽에서는 텍스트와 이미지를 한 벡터 공간에 넣는 멀티모달 임베딩으로, 문장으로 사진을 찾는 검색이나 이미지가 섞인 문서의 RAG를 구현한다.

주의할 점

모달리티가 늘수록 비용 구조가 달라진다. 이미지는 해상도에 따라 수백~수천 토큰으로 환산되어 과금되므로, 고해상도 스크린샷을 대화마다 반복해 넣으면 요금이 가파르게 뛴다. 환각도 텍스트보다 교묘하다. 차트의 수치를 그럴듯하게 잘못 읽거나 이미지에 없는 요소를 있다고 답하는 경우가 있어, 수치가 중요한 작업이라면 원본 데이터 검증 단계를 함께 설계하는 것이 안전하다. 해상도도 트레이드오프다. 이미지를 줄여 보내면 토큰이 절약되지만 작은 글씨가 뭉개지고, 원본 그대로 보내면 정확하지만 비싸다. 문서 이미지라면 긴 변 기준으로 적정 해상도를 실험해 파이프라인에 고정해 두는 것이 좋다. 보안 관점에서는 이미지 속에 사람 눈에 안 띄게 심어둔 지시문을 모델이 읽고 따라버리는 이미지 프롬프트 인젝션이 새로운 공격면이 됐다. 사용자가 올린 이미지를 에이전트가 처리하는 서비스라면, 텍스트 입력만 검증하던 시절의 가드레일로는 부족하다는 뜻이다. 멀티모달은 편의만큼 공격면과 비용 축도 함께 늘리는 기술이라, 입력 형태별 한도와 검증을 설계 단계에서 정해두는 것이 안전하다.
