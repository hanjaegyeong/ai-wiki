MCP

Model Context Protocol

AI 모델이 외부 도구와 데이터에 접근하기 위한 표준 프로토콜. USB-C가 기기를 하나의 규격으로 연결하듯, MCP는 AI와 외부 시스템을 하나의 방식으로 연결한다.

연결을 만들 때마다 새로 짜던 시절

AI 에이전트가 쓸모 있으려면 외부 세계와 연결되어야 한다. GitHub 이슈를 읽고, 사내 DB를 조회하고, Slack에 메시지를 보내야 한다. 문제는 이 연결을 앱마다, 서비스마다 따로 만들어야 했다는 것이다. AI 앱이 M개, 연결할 도구가 N개면 M×N개의 통합 코드가 필요한 구조였다. MCP는 2024년 11월 Anthropic이 이 문제를 풀기 위해 공개한 오픈 프로토콜이다. USB-C가 기기마다 다르던 단자를 하나로 통일했듯, MCP 서버 하나만 만들면 이를 지원하는 모든 AI 클라이언트가 같은 방식으로 그 서비스에 접근한다.

프로토콜이 실제로 정한 것

구조는 클라이언트-서버다. Claude Code나 Cursor 같은 AI 앱이 클라이언트가 되고, 외부 시스템 쪽에 MCP 서버를 세운다. 서버가 노출할 수 있는 것은 세 가지다. 도구는 모델이 호출하는 실행 가능한 기능(이슈 생성, 쿼리 실행), 리소스는 모델이 읽을 수 있는 데이터(파일, 문서), 프롬프트는 재사용 가능한 지시 템플릿이다. 연결 시점에 양쪽이 지원 기능을 교환하는 핸드셰이크를 거치며, 통신은 JSON-RPC 기반으로 로컬 프로세스면 stdio, 원격 서버면 HTTP로 주고받는다. 프로토콜이 이 규격을 못 박아 둔 덕분에, 서버를 만드는 쪽은 어떤 클라이언트가 붙을지 신경 쓰지 않아도 된다. 원격 서버는 OAuth로 인증을 처리하는 규격까지 정의되어 있어서, 회사 밖의 SaaS 서비스가 공식 MCP 서버를 제공하는 형태로도 확산되고 있다.

한 회사의 규격에서 업계 표준으로

공개 초기엔 Anthropic 생태계의 물건이었지만, 2025년 OpenAI, Google DeepMind, Microsoft가 잇따라 지원을 발표하면서 사실상의 업계 표준이 됐다. 2025년 12월에는 Anthropic이 MCP를 Linux Foundation 산하 재단에 기부해서, 특정 회사가 아닌 커뮤니티가 관리하는 중립 표준이 됐다. 지금은 GitHub에 MCP 서버 레포가 수만 개에 달하고, 공식 레지스트리에서 필요한 서버를 검색해 설치하는 생태계가 자리 잡았다. 파일시스템, GitHub, Slack, 구글 드라이브처럼 자주 쓰는 서비스는 이미 만들어진 서버를 가져다 쓰면 된다. 경쟁사들이 같은 프로토콜 위에 모인 덕에, 개발자는 도구 연동 코드를 한 번만 짜면 된다.

개발자가 만나는 장면

쓰는 쪽은 간단하다. Claude Code에서 claude mcp add로 서버를 등록하면 에이전트가 그 서비스의 도구를 바로 쓸 수 있다. Playwright MCP를 붙이면 에이전트가 직접 브라우저를 조작해 자기가 만든 UI를 눈으로 확인하고, PostgreSQL MCP를 붙이면 실제 데이터를 조회하면서 코드를 짠다. 만드는 쪽도 부담이 낮다. Python이나 TypeScript SDK로 함수 몇 개에 데코레이터를 붙이면 사내 API가 MCP 서버가 되고, 한 번 만들면 Claude Code, Cursor, ChatGPT 등 MCP를 지원하는 모든 클라이언트에서 재사용된다. 예를 들어 사내 배포 시스템에 MCP 서버를 하나 얹어 두면, 개발자마다 쓰는 AI 도구가 달라도 "스테이징에 배포하고 로그 보여줘"라는 요청이 전부 같은 서버를 통해 처리된다. 연동 코드를 도구 개수만큼 만들던 일이 서버 하나 관리하는 일로 줄어드는 것이다.

도구가 많아질 때 생기는 문제

서버를 붙일수록 도구 정의가 컨텍스트를 잡아먹는다. 도구 수십 개의 설명이 매 요청에 실려 가면 그 자체로 토큰이 상당해서, Anthropic은 도구 정의를 코드 API처럼 두고 에이전트가 필요한 것만 찾아 호출하게 하는 방식을 제안하기도 했다. 보안도 남은 숙제다. MCP 서버는 에이전트에게 새 능력을 주는 동시에 새 공격 표면이 된다. 출처가 불분명한 서버가 악의적인 도구 설명으로 에이전트를 조종하거나, 도구가 반환한 콘텐츠 속에 프롬프트 인젝션이 숨어 들어올 수 있다. 검증된 서버만 붙이고, 에이전트에게 꼭 필요한 권한만 주는 게 현실적인 수칙이다. 프로토콜은 표준이 됐지만, 그 위에서 무엇을 얼마나 열어 줄지는 여전히 설계하는 사람의 몫이라는 얘기다.
