클로드 코드

Claude Code CLI

터미널에서 자연어로 코드베이스를 이해하고, 파일을 편집하고, Git 워크플로우 전체를 자율적으로 수행하는 AI 코딩 에이전트.

터미널로 들어온 코딩 에이전트

Claude Code는 에디터 플러그인이 아니라 터미널에서 도는 에이전트다. 자연어로 지시하면 코드베이스를 탐색해 맥락을 파악하고, 파일을 편집하고, 셸 명령과 테스트를 실행하고, 커밋과 PR까지 만든다. 에디터 안에서 다음 줄을 제안받는 방식과 달리, 작업 하나를 통째로 맡기고 결과를 검토하는 방식에 가깝다. 터미널이라는 선택 덕분에 SSH로 접속한 원격 서버든 CI 환경이든, 에디터가 없는 곳 어디서나 같은 방식으로 쓸 수 있다. 지금은 CLI 외에 VS Code·JetBrains 확장, 데스크톱 앱, 웹 버전까지 나와 있지만, 핵심 동작 방식은 어디서든 같다. 지시를 받으면 도구를 골라 실행하고 결과를 보고 다음 행동을 정하는 에이전트 루프다.

한 세션이 흘러가는 모습

"주문 취소 API에 환불 로직 추가해줘"라고 하면, 에이전트가 먼저 라우터와 서비스 코드를 훑어 기존 구조를 파악하고, 수정할 파일과 접근 방식을 정한 뒤 편집을 시작한다. 큰 작업이라면 플랜 모드로 계획만 먼저 세우게 해서 사람이 방향을 승인한 다음 실행시킬 수 있다. 수정이 끝나면 테스트를 돌리고, 실패하면 에러를 읽고 다시 고치는 루프를 스스로 반복한다. 위험한 명령은 실행 전에 권한을 물어보므로, 처음엔 하나하나 승인하다가 신뢰가 쌓이면 허용 범위를 넓혀 가는 식으로 길들인다. 에이전트가 파일을 잘못 건드렸다면 체크포인트로 이전 상태로 되감을 수 있어서, 과감하게 맡기고 결과를 보고 판단하는 작업 방식이 성립한다.

컨텍스트를 많이 잡아먹는 대규모 탐색은 서브에이전트에 위임한다. 리팩토링 영향 범위 조사를 서브에이전트 여러 개가 나눠 맡으면, 각자 독립된 컨텍스트 윈도우에서 파일을 읽고 결론만 메인 세션에 보고하기 때문에, 본 세션의 컨텍스트를 아끼면서 넓은 코드베이스를 병렬로 다룰 수 있다. 서브에이전트는 .claude/agents/에 마크다운 파일로 정의하는데, 리뷰 전담, 테스트 전담처럼 역할과 사용할 도구, 모델까지 지정해 두면 필요할 때 자동으로 불려 나온다.

내 프로젝트에 맞게 길들이기

프로젝트 루트에 CLAUDE.md를 두면 세션 시작 때 자동으로 읽혀서 코딩 컨벤션, 빌드 명령, 금지 사항 같은 규칙이 매번 적용된다. 반복 워크플로우는 스킬로 만들어 /commit, /deploy처럼 슬래시 커맨드 한 줄로 실행하고, 훅을 걸면 파일 수정 직후 린트 실행처럼 정해진 시점에 반드시 도는 자동화를 심을 수 있다. 모델의 판단에 맡기는 스킬과 달리 훅은 셸 스크립트라서 예외 없이 실행된다는 게 차이다. 외부 연결은 MCP로 한다. GitHub MCP 서버를 붙이면 이슈를 읽고 PR을 만들며, 사내 DB의 MCP를 붙이면 스키마를 조회하면서 코드를 짠다. 이런 구성 요소들을 플러그인 하나로 묶어 팀 전체에 배포하는 것도 가능하다.

사람 없이 돌아가는 곳까지

대화형으로만 쓰는 도구가 아니다. claude -p 헤드리스 모드로 실행하면 스크립트나 CI 파이프라인 안에서 결과만 출력하고 종료한다. 매일 아침 크론으로 이슈 트리아지를 시키거나, PR이 열릴 때마다 자동 리뷰를 붙이는 자동화가 이 모드로 만들어진다. GitHub Actions용 공식 액션이 있어서 리포지토리에 몇 줄 추가하면 이슈에 멘션만 해도 에이전트가 작업을 시작한다. Claude Code 자체가 Claude Agent SDK 위에 구현되어 있어서, 같은 기반 위에 자신만의 에이전트를 만드는 것도 가능하다. 이 위키의 일일 키워드 수집 파이프라인처럼, 사람이 자는 동안 돌아가는 콘텐츠 자동화에도 흔히 쓰인다.

잘 쓰는 요령

한 번에 거대한 작업을 던지기보다 검증 가능한 단위로 쪼개서 시키는 게 결과가 좋다. 테스트가 있는 코드베이스일수록 에이전트가 자기 변경을 스스로 검증하며 진행할 수 있어서 자율성을 더 줘도 안전하다. 대화가 길어지면 컨텍스트가 자동 압축되면서 초반에 합의한 세부 사항이 옅어질 수 있으니, 긴 작업은 단계마다 세션을 끊고 진행 상태를 CLAUDE.md나 계획 파일에 남겨 두는 편이 안정적이다. 결국 Claude Code를 잘 쓴다는 건 좋은 지시문을 넘어서, 규칙 파일과 스킬과 훅으로 에이전트가 일하기 좋은 환경을 설계하는 일에 가깝다. 같은 모델이라도 이 환경을 어떻게 짜느냐에 따라 결과물의 품질이 크게 갈린다.
