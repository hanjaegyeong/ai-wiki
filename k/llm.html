대규모 언어 모델

Large Language Model

수백억 개의 파라미터로 학습한 딥러닝 모델. 텍스트 이해, 생성, 추론, 코드 작성 등 광범위한 작업을 수행하는 현재 AI 기술의 핵심이다.

다음 단어 맞히기가 지능이 되기까지

대규모 언어 모델의 학습 목표는 허무할 만큼 단순하다. 인터넷에서 긁어모은 수조 개의 토큰을 보여주면서 "다음에 올 토큰이 뭘까"를 맞히게 하는 것, 그게 전부다. 그런데 이 게임을 정말 잘하려면 생각보다 많은 걸 알아야 한다. "프랑스의 수도는"에 이어질 단어를 맞히려면 지리 지식이 필요하고, "따라서 x의 값은"을 완성하려면 앞의 수식을 실제로 풀어야 하며, 소설 속 대사를 자연스럽게 이어가려면 등장인물의 심리까지 추적해야 한다. 다음 토큰 예측이라는 단순한 목표를 수천억 개의 파라미터와 방대한 데이터로 밀어붙이자, 따로 가르친 적 없는 번역·요약·코드 작성·수학 추론 능력이 함께 딸려 나왔다. GPT(OpenAI), Claude(Anthropic), Gemini(Google), Llama(Meta)가 모두 이 출발점을 공유한다.

덩치를 키우면 실력이 는다는 발견

이 분야를 폭발시킨 건 스케일링 법칙이다. 파라미터 수, 데이터양, 계산량을 늘리면 모델의 성능이 예측 가능한 곡선을 따라 꾸준히 좋아진다는 관찰인데, 2020년 OpenAI가 이를 수식으로 정리한 뒤 업계 전체가 "더 크게"라는 한 방향으로 달렸다. 1,750억 파라미터의 GPT-3가 그 증명이었고, 이후 프론티어 모델들은 정확한 크기를 공개하지 않을 만큼 커졌다. 다만 2024년 이후 흐름이 달라졌다. 모든 파라미터를 매번 쓰는 대신 필요한 전문가 블록만 활성화하는 MoE(전문가 혼합) 구조로 비용을 억제하고, 무작정 키우기보다 답하기 전에 생각을 길게 풀어 쓰는 추론 모델 학습에 계산을 투자하는 쪽으로 무게중심이 옮겨갔다. 같은 모델이라도 생각할 시간을 더 주면 어려운 문제를 더 잘 푼다는 게 확인됐기 때문이다.

혼자서는 못 하는 것들

LLM의 지식은 학습이 끝난 시점에 얼어붙는다. 어제 나온 라이브러리 버전은 모르고, 회사 내부 문서는 본 적이 없다. 게다가 모르는 것을 모른다고 하는 대신 그럴듯한 문장을 지어내는 환각이 있고, 스스로 파일을 열거나 API를 부를 수도 없다. 그래서 현재 AI 애플리케이션 개발의 골격은 이 빈틈을 바깥에서 메우는 일이다. 최신 정보와 사내 지식은 RAG로 검색해서 컨텍스트에 넣어주고, 외부 시스템 접근은 Tool Use나 MCP로 연결하고, 출력은 가드레일로 검증한다. LLM을 "모든 걸 아는 오라클"이 아니라 "컨텍스트에 넣어준 것을 잘 처리하는 강력한 추론 엔진"으로 보는 관점이 실무에서는 훨씬 유용하다.

토큰, 컨텍스트, 온도 — 다룰 때의 기본 단위

LLM을 실제로 만지기 시작하면 세 가지 개념이 계속 따라다닌다. 먼저 토큰. 모델은 글자나 단어가 아니라 토큰이라는 조각 단위로 텍스트를 읽고 쓰는데, 영어는 단어 하나가 대략 토큰 1~2개지만 한국어는 같은 내용도 토큰을 더 많이 쓰는 편이라 비용 계산에서 체감 차이가 난다. 다음은 컨텍스트 윈도우. 모델이 한 번에 볼 수 있는 토큰 수의 상한으로, 요즘 모델은 수십만 토큰까지 늘었지만 무한하지 않고, 길어질수록 비용이 늘며 중간 내용을 놓치는 경향도 생긴다. 마지막으로 온도(temperature) 같은 샘플링 파라미터다. LLM의 출력은 "다음 토큰의 확률 분포"에서 뽑는 추첨이라 기본적으로 비결정적인데, 온도를 낮추면 가장 확률 높은 토큰 위주로 뽑아 일관된 답이, 높이면 다양하고 창의적인(때로 엉뚱한) 답이 나온다. 같은 프롬프트에 답이 매번 달라지는 이유가 여기 있다.

개발자 관점에서 본 LLM

실제로 만질 때는 두 갈래다. 하나는 API 호출로, 시스템 프롬프트로 역할을 정하고 구조화된 출력(JSON 스키마)으로 형식을 강제하며, 입력과 출력 토큰 수에 비례해 비용을 낸다. Claude Code나 Cursor 같은 AI 코딩 도구도 결국 이 API 위에 파일 읽기·명령 실행 같은 도구를 얹은 하네스다. 다른 하나는 Llama, Qwen, DeepSeek처럼 가중치가 공개된 오픈 웨이트 모델을 직접 서빙하는 것으로, 데이터를 외부로 보낼 수 없거나 호출량이 많아 API 비용이 부담될 때 선택한다. 2026년 현재 프론티어 모델들의 경쟁 축은 단답형 챗봇 성능이 아니라, 몇 시간짜리 작업을 도구를 써가며 스스로 완수하는 에이전트 능력으로 이동했다. LLM을 이해한다는 건 이제 모델 하나가 아니라, 그 위에 쌓이는 애플리케이션 계층 전체의 기반을 이해하는 일이 됐다.
