머신러닝

Machine Learning

명시적 규칙 없이 데이터에서 패턴을 학습해 예측하는 AI 기술. 딥러닝과 LLM의 토대이자, 여전히 많은 실용적 문제에서 직접 쓰이는 도구다.

규칙을 짜는 대신 데이터에서 배운다

스팸 메일을 걸러내는 프로그램을 만든다고 해보자. 전통적인 방법은 사람이 규칙을 짜는 것이다. '무료라는 단어가 있으면 스팸', '발신자가 주소록에 없고 링크가 3개 이상이면 스팸' 같은 조건문을 계속 쌓는다. 문제는 스팸 발송자가 수법을 바꿀 때마다 규칙을 다시 짜야 하고, 규칙이 수백 개가 되면 서로 충돌하기 시작한다는 것이다. 머신러닝은 접근을 뒤집는다. 스팸 메일 수만 통과 정상 메일 수만 통을 컴퓨터에 주고 '구분하는 법을 스스로 찾아내라'고 시킨다. 사람이 규칙을 명시하는 대신, 데이터에 숨어 있는 패턴을 알고리즘이 통계적으로 찾아내는 것 — 이게 머신러닝의 본질이다.

세 가지 배우는 방식

배우는 방식은 크게 셋으로 나뉜다. 지도학습은 문제와 정답을 쌍으로 주고 가르치는 방식이다. '이 메일은 스팸, 저 메일은 정상'이라는 라벨이 붙은 데이터로 학습해서, 처음 보는 메일에 대해 답을 예측한다. 실무에서 쓰이는 머신러닝의 대부분이 여기에 속한다. 비지도학습은 정답 없이 데이터만 주고 구조를 찾게 한다. 고객 구매 기록을 던져 주면 '비슷한 소비 패턴의 그룹 다섯 개'를 알아서 묶어내는 식이다. 강화학습은 정답 대신 보상을 준다. 게임에서 이기면 점수를 주고 지면 깎는 걸 반복하면, 에이전트가 시행착오 끝에 이기는 전략을 스스로 익힌다. 바둑을 정복한 AlphaGo도, ChatGPT를 사람 말 잘 듣게 다듬은 RLHF도 강화학습의 응용이다.

LLM 시대에도 클래식 ML이 사는 이유

요즘은 AI라고 하면 LLM부터 떠올리지만, 머신러닝은 LLM보다 훨씬 큰 우산이다. 딥러닝도, 그 위의 LLM도 머신러닝의 한 갈래일 뿐이고, 신경망을 쓰지 않는 클래식 알고리즘들 — 의사결정 트리, 랜덤 포레스트, XGBoost, 로지스틱 회귀 — 은 지금도 현역이다. 특히 엑셀 표처럼 행과 열로 정리된 정형 데이터에서는 클래식 ML이 LLM보다 낫다. 고객 이탈 예측, 카드 사기 탐지, 수요 예측 같은 문제에서 XGBoost는 몇 초 만에 학습되고, 추론 비용이 거의 없고, 어떤 변수가 예측에 얼마나 기여했는지 설명까지 된다. 같은 일을 LLM에게 시키면 느리고 비싸고 근거도 흐릿하다. 라벨된 데이터가 충분하고 예측 대상이 명확하다면 클래식 ML이 여전히 최선인 경우가 많다.

직접 해보면 어떤 흐름인가

파이썬 생태계 기준으로 흐름은 이렇다. 데이터를 pandas로 불러와 정리하고, scikit-learn으로 데이터를 학습용과 시험용으로 나눈 뒤 모델을 학습시키고, 시험용 데이터로 정확도를 잰다. 코드로는 model.fit(X_train, y_train) 한 줄이 학습의 전부다. 진짜 시간이 드는 건 그 앞뒤로, 어떤 데이터를 넣을지 고르고 다듬는 피처 엔지니어링과 결과를 검증하는 과정이다. 실무에서는 여기에 실험 기록(MLflow), 모델 배포와 재학습 자동화(MLOps)가 붙는다. 배포가 끝이 아니라는 점도 머신러닝의 특징이다. 세상이 변하면 데이터의 분포도 변해서 — 소비 패턴이 바뀌고 사기 수법이 진화해서 — 한때 잘 맞던 모델의 성능이 서서히 미끄러진다. 이를 드리프트라고 부르는데, 그래서 운영 중인 모델은 성능을 계속 감시하다가 주기적으로 새 데이터로 다시 학습시킨다.

흔히 빠지는 함정

초심자가 가장 먼저 만나는 함정은 과적합이다. 모델이 학습 데이터를 통째로 외워버려서 연습 문제는 다 맞히는데 실전 문제는 못 푸는 상태다. 학습에 쓰지 않은 데이터로 반드시 검증해야 하는 이유다. 또 하나는 데이터 품질이다. 편향되거나 오염된 데이터로 배운 모델은 그 편향을 그대로 재생산한다. '쓰레기를 넣으면 쓰레기가 나온다'는 오래된 격언이 머신러닝에서는 법칙에 가깝다. 더 교묘한 함정은 데이터 누수다. 예측 시점에는 알 수 없는 정보 — 예컨대 '고객이 이탈했는가'를 예측하는 모델에 해지 처리 날짜가 슬쩍 들어가 있는 경우 — 가 학습 데이터에 섞이면, 개발 중에는 정확도가 환상적으로 나오다가 실전에서 무너진다. 머신러닝 프로젝트가 실패하는 이유는 대개 알고리즘이 아니라 이런 데이터 문제이고, 그래서 경험 많은 실무자일수록 모델을 고르는 시간보다 데이터를 의심하는 시간이 길다.
