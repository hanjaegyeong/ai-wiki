모델

파인튜닝

Fine-Tuning

사전 학습된 모델을 특정 도메인 데이터로 추가 학습시키는 기법. LoRA 덕분에 GPU 한 장으로도 가능해져서 접근성이 크게 낮아졌다.

모델의 말투와 실력을 바꾼다는 것

범용 LLM은 세상의 거의 모든 걸 조금씩 배웠지만, 특정 회사의 법률 문서 양식이나 의료 용어, 사내 코드 컨벤션처럼 좁고 깊은 영역에서는 어설플 때가 있다. 파인튜닝은 이 모델을 우리 데이터로 한 번 더 학습시켜서, 매번 프롬프트로 장황하게 설명하지 않아도 원하는 방식으로 답하게 만드는 과정이다. 흔히 오해하는데, 파인튜닝은 새로운 지식을 채워 넣는 것보다 정해진 형식, 말투, 판단 기준을 몸에 익히게 하는 데 훨씬 강하다. 지식은 가중치 깊숙이 분산 저장되어 있어 수천 건의 예시로는 잘 바뀌지 않지만, 행동 양식은 표면에 가까워 적은 데이터로도 확실히 잡힌다. 그래서 최신 정보를 계속 알아야 하는 일에는 RAG가, 일관된 형식과 톤과 도메인 감각을 원하는 일에는 파인튜닝이 어울린다. 둘은 경쟁 관계가 아니라 보통 함께 쓰인다.

어떻게 학습시키나

기본 재료는 질문과 이상적인 답변을 짝지은 예시 묶음이다. 보통 한 줄에 대화 한 쌍씩 담은 JSONL 파일로 만들어 두고, 이걸 모델에게 반복해서 보여주며 답을 흉내 내도록 가중치를 조금씩 조정한다. 이 단계를 지도 파인튜닝(SFT)이라 부른다. 예전에는 수십억 개 파라미터를 통째로 다시 학습해야 해서 값비싼 GPU 여러 장이 필요했다. 지금은 LoRA 방식이 판도를 바꿨다. 원래 모델은 얼려 두고, 각 층 옆에 아주 작은 보조 행렬 한 쌍만 새로 붙여서 그것만 학습한다. 전체의 1퍼센트도 안 되는 부분만 건드리는데도 성능은 통짜 학습에 거의 근접한다. 여기에 원본 모델을 4비트로 압축해 메모리를 더 아끼는 QLoRA를 쓰면 24GB짜리 소비자용 GPU 한 장으로 7~8B 모델을 무리 없이 다룰 수 있다. 직접 하려면 Hugging Face의 peft나 학습 속도를 끌어올린 Unsloth를 쓰고, 인프라 관리가 부담이면 OpenAI 등의 관리형 파인튜닝에 JSONL 파일만 올리는 방법도 있다.

흉내 다음 단계, 선호 학습

SFT는 "이렇게 답해라"라는 정답을 그대로 따라 하게 만드는 방법이라, 좋은 답과 아쉬운 답의 미묘한 차이까지는 가르치기 어렵다. 그래서 요즘 파이프라인은 SFT 뒤에 선호 학습을 한 단계 더 얹는다. 같은 질문에 대한 두 응답 중 어느 쪽이 나은지 표시한 데이터로 학습하는 DPO가 대표적인데, 복잡한 강화학습 없이 파인튜닝과 거의 같은 코드로 돌릴 수 있어 표준이 됐다. 상용 모델들이 거치는 RLHF의 간소화 버전을 개인 프로젝트에서도 쓸 수 있게 된 셈이다. 수학이나 코드처럼 정답을 기계적으로 채점할 수 있는 영역이라면, 채점 결과를 보상으로 삼아 강화학습(RLVR)까지 가는 것이 2025년 이후 추론 모델들의 레시피다.

먼저 다른 방법부터 시도하라

파인튜닝은 강력하지만 대개 마지막 카드다. 프롬프트를 다듬거나 RAG로 문서를 붙여서 풀리는 문제라면 굳이 학습까지 갈 이유가 없다. 학습 데이터를 모으고 다듬는 손이 많이 가고, 원본 모델이 새 버전으로 올라가면 처음부터 다시 학습해야 하기 때문이다. 또 하나 조심할 건 파괴적 망각이다. 좁은 데이터만 집중해서 먹이면 정작 원래 잘하던 일반 상식이나 추론 능력이 흐려질 수 있다. 그래서 특화 데이터에 일반적인 예시를 적당히 섞고, 학습 뒤에는 기존 실력이 유지되는지 평가 세트로 함께 점검해야 한다. 실무에서 자주 터지는 함정 하나 더 — 학습 때 쓴 채팅 템플릿(시스템·유저 역할 표기, 특수 토큰)과 서빙 때의 템플릿이 어긋나면 성능이 이유 없이 떨어진 것처럼 보인다. 파인튜닝이 실패한 것 같을 때 가장 먼저 확인할 지점이다.

정리하면 판단 순서는 이렇다. 프롬프트 개선으로 되는가 → 예시 몇 개를 프롬프트에 넣는 퓨샷으로 되는가 → RAG로 지식을 붙이면 되는가 → 그래도 형식·톤·도메인 감각이 부족한가. 마지막 질문에 "그렇다"일 때, 그리고 품질 좋은 예시를 수백~수천 건 만들 수 있을 때가 파인튜닝의 자리다. 반대로 작은 오픈 모델을 파인튜닝해서 대형 모델 API를 대체하면 응답 속도와 비용, 데이터 주권을 한꺼번에 얻는 경우도 많아서, "작고 특화된 모델이 크고 범용인 모델을 이긴다"는 것이 파인튜닝을 선택하는 가장 흔한 실전 동기다.
